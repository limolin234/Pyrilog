# 设计哲学与取舍

## 核心目标

Pyrilog 让用户用 Python 描述器件接口、参数、拓扑和局部等式。长期的
**目标抽象**是把它们统一装配为

\[
F(x, \dot{x}, s, t, p, h)=0.
\]

这里的符号概括连续未知量及导数、分析变量、时间、参数和历史依赖，不表示
这些字段已经存在于当前 IR。当前实现仍是对象图、有限规范形匹配和显式
Verilog-A contribution，没有一般 residual/SystemIR。Pyrilog 首先是关系建模
语言和编译层，不是现阶段重写一套完整求解器。

## 不变量

1. **用户只写接口、参数和关系。** 注册、拓扑提取、稳定 ID、量纲检查、
   方程包装和后端装配属于框架。
2. **所有可实例化模块都是 `Device`。** 原子器件和复合器件递归同构，
   不为 subcircuit 再建一套用户类型。
3. **拓扑语义由物理域决定。** 电和热是守恒节点；光是严格二元参考面连接。
4. **精确映射优先于自动猜测。** 不能证明等价时报错，不静默加寄生、
   `gmin`、RLC 或延时近似。
5. **量纲是模型契约。** 参数、节点元数和 relation 在进入后端前检查，
   单位不只是输出标签。
6. **生成物必须可审计。** 稳定层次 ID、SPICE、Verilog-A 和 manifest
   共同保留源模型到后端对象的映射。

## 为什么嵌入 Python

Python 直接提供对象、类体执行、反射、运算符重载、复数字面量和通用容器。
因此 v1 不需要先设计 parser、循环或数组语法。代价是 Python 的执行顺序也成为
语言契约：类体和 `with Circuit()` 中都必须先实例化、后连接。

局部 Python 变量名无法稳定反射，所以内部 ID 不依赖 `r1` 这类运行时局部名；
类成员名和注册顺序才是稳定命名依据。

## 关键取舍

| 选择 | 获得 | 牺牲或边界 |
| --- | --- | --- |
| 普通数值自动反射为参数 | 常用模型接近普通 Python 类 | 非参数常量要用 `ClassVar`；高级元数据要用 `param()` |
| `|` / `|=` 构建拓扑 | 连接紧凑，可返回有名节点 | 需要理解 Python 运算顺序；光不允许任意多端链 |
| 局部等式而非手写 stamp | 模型可读、可换后端 | 编译器必须做严格的结构分类；当前不支持任意隐式残差 |
| 标准器件用保留 SPICE 元数据 | 精确、高效、可复用后端模型 | 不能宣称它们是从任意 relation 普遍推导出来的 |
| 未匹配的受支持关系生成 Verilog-A | 保留非线性和 `ddt` | 受 OpenVAF/ngspice 支持子集限制 |
| 热域映射为电类比 MNA | 直接复用 SPICE KCL 和积分器 | 尺度映射可导致病态；自动归一化尚未实现 |
| 先复用成熟求解器 | 减少 DAE、时间积分和收敛工作量 | accepted-step hook、光复数和多速率受后端能力约束 |
| Controller 不伪装成 MNA 节点 | 连续物理和离散调度边界清楚 | 当前只有 Feedback IR，没有可执行调度器 |

## 已否定或不采用的路线

- 不因为器件出现 `C: J/K` 就自动生成隐式 `T/P/TP`。现在用显式
  `tnode(C=...)`，一个器件可拥有多个热节点。
- 不为每个原生 SPICE 实例生成独立器件文件。原生实例内联到主网表或
  `.subckt`，仅共享的 Verilog-A 模型产生独立文件。
- 不把光端口当成电 KCL 节点。分光、合光、反射和损耗由显式器件关系描述。
- 不把波导损耗或延时放在连接器上。连接只定义拓扑等价，传播是器件。
- 不将任意 `ddt` 或非线性关系自动拼成 RLC。只在可证明的受限类上做精确优化。
- 不用关系数量检查冒充一般秩证明。当前 budget 只是保守结构护栏。
- 不扫描任意 `__init__` 形参或编译任意 Python 函数；只接受框架建立的类型表达式树。

## 优化原则

前端先保留物理信息，然后才能优化。层次保留、原生器件选择、复数标量化、
归一化和内部节点生成都应是可独立验证的 pass。优化可以改变表示，不能改变
方程集的解。
